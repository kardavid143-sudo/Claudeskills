# PMU role contracts

Assign a single accountable owner per output. Combine lightweight roles where useful; keep substantive review separate from authorship.

| Base position | Own | Handoff | Boundary / adaptation |
| --- | --- | --- | --- |
| Team Lead / Project Management Expert | PMU method, decomposition, dependencies, synthesis, escalation | Plan, task graph, result, unresolved issues | Do not change mandate or accept own work; Architect/Integrator for technical tasks |
| Programme Implementation Expert | Milestones, feasibility, operational issues, execution | Output or actionable plan with owners/sequencing | Track execution, not redefine indicators; Coder/Builder for software |
| M&E / RBM Expert | Results chain, indicators, acceptance, outcomes, evaluation | Indicator definitions, baseline/target distinctions, checks | Do not infer impact from activities; Reviewer/Test Designer when independent |
| MIS & Data Analytics Expert | Data grain/schema, integration, reconciliation, analytics | Reproducible calculations/code, quality register, source mapping | Do not certify unsupported data; Data Engineer/Analyst |
| Government Coordination & Stakeholder Engagement Expert | Institutions, decisions, consultations, requirements | Stakeholder map, dependencies, coordination needs | Research/draft only; no unauthorized contacts/submissions; Explorer/Requirements Researcher |
| Capacity Building & Institutional Strengthening Expert | Adoption, training, SOPs, handover, maintainability | Adoption plan, SOP/learning materials, safeguards | Do not present workshops as outcomes; Operational Readiness Specialist |
| Documentation & Knowledge Management Specialist | Evidence index, terminology, assembly, versions | User-ready output and evidence pointers | No invented facts or promotion of drafts to approvals; Writer/Editor |

## Recipes

- Research: Lead + Researcher + Analyst + Documentation; an unaffiliated member or separate reviewer verifies.
- M&E: Lead + M&E + Data + Documentation; add implementation/adoption if operationalization is requested.
- Software: Lead/Architect + Explorer + Coder + Reviewer; preserve independent verification.
- Government report: Lead + Evidence/Data + M&E + Documentation; add institutional/adoption specialists as needed.
- Narrow extraction/edit: one unit with author/reviewer split; avoid unnecessary roles.

## Worker brief

```
Run / PMU / task / role: <IDs>
Canonical mandate: <brief path + SHA-256; no assumed chat context>
Objective and acceptance: <bounded output>
Approach lens: <method and meaningful tradeoff>
Read as needed: <role guide, sources, accepted dependencies>
Allowed sources/constraints: <exact mandate policy>
Output directory: <assigned absolute directory>
Ledger / claim token / expiry: <actual returned values>
Artifact requirements: <format, evidence, checks, uncertainty>
Communication: <blockers to Lead; Director owns user intake>
Budget: <bounds; no nested spawning/hidden follow-up calls>
Completion: <submit via tracker; concise receipt>
Provide conclusions, evidence, assumptions, and concise decision reasons.
Do not return private chain-of-thought.
```

Keep the common mandate identical. Tailor assignments, lenses, relevant sources/dependencies, and output locations. Give reviewers neutral artifacts and rubric, not a preferred answer.
